# 私人数据跨设备迁移

源码通过 GitHub 同步。参考 PDF、转录频率、计算结果及审计仍保存在被 Git 忽略的 `data/private/`，通过本人设备间的数据包迁移。工具只访问本机文件，不上传内容，也不会把私人文件加入 Git。

## 导出、检查与恢复

在已有数据的电脑，从项目根目录运行：

```powershell
python scripts/pack-local-data.py
```

输出会给出 `data/private/exports/` 下的新 ZIP 路径。将该 ZIP 复制到另一台电脑，先克隆或更新项目源码。工具默认以当前脚本所在项目为目标；也可用 `--root` 明确指定另一份工作区。

```powershell
# 只检查压缩包，不恢复
python scripts/pack-local-data.py --verify "D:/transfer/你的数据包.zip"

# 可选：预览新增文件和相同文件数量，目标工作区不产生任何文件
python scripts/pack-local-data.py --restore "D:/transfer/你的数据包.zip" --dry-run

# 恢复至当前项目
python scripts/pack-local-data.py --restore "D:/transfer/你的数据包.zip"

# 或恢复至另一个已存在的项目目录
python scripts/pack-local-data.py --root "D:/projects/GTO_Reminder" --restore "D:/transfer/你的数据包.zip"
```

恢复规则固定为：

- 文件不存在：验证后新增。
- 同名文件的大小与 SHA-256 一致：跳过，保留原文件及修改时间。
- 任意同名文件内容不同：整批预检拒绝，不覆盖、不自动选择更新日期较晚的版本。
- 不在包内的现有文件保持原样。包内清单不会覆盖目标项目已有的清单文件。

同一个数据包可以重复运行；已完整恢复时会返回 `state: unchanged` 和跳过数量。出现冲突时，先在另一份干净项目中恢复并核对需要保留的版本，或自行备份并移走已明确不再使用的冲突文件，再重新执行。工具没有强制覆盖参数。

## 导入期间与中断恢复

恢复先固定压缩包副本、检查完整清单及全部摘要，并在私人事务目录中暂存。只有这些检查完成后才取得导入锁并发布文件。每个文件使用同卷、排他的硬链接完整落位，已有同名文件无法被该操作覆盖。源目录和目标目录必须位于支持硬链接的同一文件系统；不支持时安全失败并回滚，不能静默退回到非排他的复制。

导入锁位于 `data/private/exports/.restore-lock`。本地数据 API 检测到锁时暂时返回 503，页面会提示稍后刷新，避免在导入未完成时读取半批数据。所有文件发布并写入完成记录后，工具才移除锁。每次发布、自动回滚或中断恢复还会先更新持久的 `.restore-generation` 标记；即使整次恢复恰好发生在 API 的两次锁检查之间，API 也会通过标记变化拒绝该次读取。这里采用**文件原子发布、批次隔离和事务回滚**，不是一次原子替换整个非空目录。

事务记录和输入 ZIP 备份保存在：

```text
.runtime/data-restores/<32 位事务 ID>/
  source.zip       固定并验证过的输入包，独立备份
  journal.json     配置、文件摘要、身份、发布与回滚状态
  .recovery-claim  恢复时的内核排他句柄所用文件，结束后保留
  payload/         暂存内容；部分文件可能与发布文件互为硬链接
```

已有文件从不被覆盖，因此无须先复制整个旧数据目录。`payload/` 的硬链接不作为独立备份使用；独立副本是 `source.zip`。这些文件同样被 Git 忽略。成功返回的信息包含事务 ID、日志路径、备份路径、新增和跳过数量。数据校验失败或冲突发生在发布前时，可能保留私人诊断副本，但不会新增活动策略文件。

一般异常会自动撤回本次新增文件。强制终止进程或电脑重启后，再执行同一恢复命令，工具会检查旧锁所属进程：原进程已退出时，根据日志先恢复一致状态，再重试；原进程仍在运行或无法判断时，不接管、不停止它。完成标记已写入但锁尚未删除的情况只清理遗留锁，不撤回成功的数据。

多个进程同时恢复同一事务时，只有取得 `.recovery-claim` 内核排他所有权的进程能继续；它取得所有权后重读日志和旧锁，并把旧锁原子更新为当前进程。其他进程会退出，不会并发写同一事务。句柄在进程退出时由系统释放，包括强制退出；文件本身保留，不需要删除。Windows 使用不共享的文件句柄，其他系统使用非阻塞 `flock`。

需要主动撤回一次已经成功的恢复时，使用返回的实际事务 ID：

```powershell
python scripts/pack-local-data.py --rollback "返回的32位事务ID"
```

回滚只处理该事务实际新建的文件，并同时检查文件身份、大小和 SHA-256。原先已存在、导入时被跳过的文件不处理；新增文件后来被编辑或被另一文件替换时，也不会删除。此时保留锁及阻塞文件列表：先把需要保留的改动移到安全位置，再按提示重试相同事务的回滚。不要通过直接删除导入锁来掩盖未完成的恢复。

Windows 下，目录句柄阻止发布期间目录被改名或换成重解析点；撤回文件时，针对已打开且禁止其他写入/替换的句柄再次核对内容后删除。在其他系统上仍执行路径和身份检查，但导入锁只约束本项目的导入工具及数据 API。恢复期间应避免外部程序写入目标私人数据或事务目录；该工具不是针对同一账户下任意恶意进程的隔离沙箱。

API 协议：`.restore-generation` 是 32 位小写 UUID 十六进制加换行，共 33 字节。工具持有导入锁后，在任何活动文件修改前，将新标记写入同目录临时文件，`flush/fsync` 后原子替换；解锁后保留。API 开始读取时先记住标记、再检查锁，返回前先比较标记、再检查锁。标记变化、锁存在或保护文件无法可靠读取时，均不返回策略数据。

## 内容范围与资源限制

只接受打包工具的固定白名单：计算用的 `computed-*.tree.json` / `*.quick.json`、五份指定转录 JSON、三份指定原始 PDF，以及 `solver-audits/` 顶层审计 JSON。`.runtime/`、完整 `.gtop` 求解存档、引擎、日志、环境变量文件和其他私人文件不在数据包中。求解存档续算见 [LOCAL_SOLVER.md](LOCAL_SOLVER.md)。

恢复拒绝绝对路径、路径穿越、反斜杠/盘符/ADS 路径、Windows 保留设备名、大小写别名冲突、ZIP 目录或链接条目、磁盘符号链接与重解析点、重复条目、加密或不支持的压缩编码、遗漏清单项、大小或摘要不符。源包在固定副本生成期间发生变化也会失败；之后只读取固定副本，原 ZIP 被替换不会改变正在恢复的内容。

当前固定上限为：

| 项目 | 上限 |
| --- | ---: |
| 压缩包 | 2 GiB |
| 全部展开内容 | 4 GiB |
| 文件数 | 10,000 份有效载荷，另加 1 份清单 |
| 单份计算策略 JSON | 20 MiB |
| 其他白名单 JSON | 32 MiB |
| 单份 PDF | 128 MiB |
| 清单 / ZIP 中央目录 | 4 MiB / 16 MiB |
| 单条目展开比例 | 1,000 倍 |

元数据边界在解压前检查，实际读取按块计数，暂存前也会检查可用空间。ZIP64 的条目头可以使用；上述大小和文件数边界内不需要 ZIP64 结束目录，因此该结束目录格式以及分卷 ZIP 不接受。

摘要校验确认传输和恢复完整性，不证明数据包作者身份、策略质量或授权范围。应用仍会独立验证实际策略格式与合法行动。私人 PDF 和频率不能因成功校验就公开上传到 GitHub。
