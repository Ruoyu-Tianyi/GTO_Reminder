# GTO_Reminder 路线图

更新日期：2026-09-27。

目标是让用户以清楚的场景条件查询可追溯的扑克策略。当前 v0.1 已建立交互和导入基础；正式翻前 GTO 辅助还依赖获授权的数据及质量核验。以下阶段按依赖关系安排，不构成上线日期承诺。

## 已实现：v0.1 交互与查询基础

- React、TypeScript、Vite 本地网页应用；默认英文，可切换中文，动作与位置保留英文。
- 2–9 人二维牌桌、位置选择、有效后手和场景参数。
- 169 类起手牌矩阵、手牌输入归一化、动作频率展示与组合加权汇总。
- RFI、Facing Open、Facing 3-Bet、Facing 4-Bet 的数据模型与完全匹配查询。
- 本地 JSON 导入、结构和行动规则校验、来源信息展示、缺少数据时的空状态。
- 4 个 6-max / 100bb 合成演示节点，持续显示演示标记。
- 手牌、位置、精确匹配、组合统计与导入验证的单元测试。

数据目前仅保留在页面内存中，刷新即清空；内置策略不来自专业 solver。详见[当前格式](DATA_FORMAT.md)。

## 下一阶段：第一个正式翻前数据包

先完成一个明确的 **6-max NLHE cash / 100bb / 指定 Rake 与下注树**，再扩展条件。相比一次覆盖所有人数，单一配置的完整性更容易核验。

1. 根据[来源调研](DATA_SOURCES.md)选择专业供应商，确认数据来源、求解设置、许可范围和导出方式。若选择 API，先验证实际鉴权、覆盖目录与响应样例。
2. 明确个人本地导入和产品发布两种用途分别允许什么，记录第三方展示、缓存和再分发权限；仅获准发布的数据随仓库或产品发布。
3. 建立转换器，保留供应商、版本、获取日期、原始文件校验值、完整求解参数和转换记录。
4. 核实动作数据是条件频率还是包含历史 reach 的范围权重，避免把两个概念混用。
5. 覆盖约定配置下的 RFI、Facing Open、Facing 3-Bet、Facing 4-Bet，并与原始供应商显示或导出逐项核对。未覆盖场景继续显示无数据。

完成标准：数据可追溯、适用条件和使用权限明确、转换验证通过、代表性混频与原始输出一致。导入文件自行声明 `imported` 不等于达到这些标准。

## 扩充翻前模型

schema v1 的范围窄于完整翻前游戏树。正式扩展时应发布新版本，而不是借用旧字段表达不同含义。

| 扩展 | 需要补充的内容 |
| --- | --- |
| 完整 SB / HU 首次行动 | Limp、Complete、Check 及后续分支；v0.1 未内置 SB RFI 数据 |
| 多人底池与 Squeeze | 有序动作历史、每位参与者、冷跟者与全部下注尺寸 |
| 多尺寸和全下 | 每个动作的独立大小、5-Bet、Shove、合法下注规则 |
| 非对称后手 | 每个座位的筹码、已投入金额、有效后手计算方式 |
| 范围汇总 | 历史 reach、节点不可达手牌及按到达范围加权的统计 |
| 更多规则 | 结构化 Rake、per-player Ante、BB Ante、Straddle 等规则 |
| 更多人数与深度 | 有对应数据的完整配置目录；不靠静默复用或插值填补 |
| 比赛决策 | 明确区分 chip EV、ICM、PKO；为后两者增加必要筹码与奖金信息 |

所有扩展继续遵守“匹配不到就不展示策略”，并为不同数据精度和简化方式提供清楚标签。

## 日常学习体验

- 可选本地持久保存、数据集删除与更新管理，让刷新不再丢失已导入数据。
- 收藏场景、快速回到常用位置与范围对比。
- 支持用户从已覆盖节点开始选择，直接看见可用后手、人数与尺寸，减少无数据组合。
- 保留中文解释与英文术语，完善手机布局、键盘操作和阅读辅助。
- 在数据质量可靠后加入练习模式，依据真实频率或 EV 评估选择；避免把少数频率动作简单判为错误。

## 翻后与完整游戏研究

先选一个已核验翻前节点产生的 heads-up 底池，例如 BTN Open、BB Call，明确起始范围、底池、后手及完整下注树。

1. 增加公共牌输入、重复牌与阻断检查、具体组合策略和 board 条件。
2. 从一个固定场景的 Flop 开始验证数据，再沿实际行动延续至 Turn、River。
3. 明确翻前 reach 如何传递到翻后，记录策略版本与节点路径；不能只凭手牌强度生成“GTO”动作。
4. 增加策略、EV、组合范围对比；较大数据采用可索引存储与按需加载。
5. 在单挑路径可靠后，再评估多路底池、比赛风险模型以及按需求解的计算与供应商方案。

## 每个阶段的验证

- 数据：频率有效、覆盖明确、无重复场景、参数与原始输出一致；记录精度与已知限制。
- 逻辑：位置顺序、动作合法性、后手和尺寸边界、组合计数、不可达与缺失节点。
- 界面：切换数据集、中文/英文、导入失败、无匹配数据、移动尺寸及可访问性。
- 工程：运行 `npm test` 和 `npm run build`，并检查主要用户流程。

来源调研与供应商条件会变化，正式获取数据时应重新核实；当前调研记录日期为 2026-09-26。
